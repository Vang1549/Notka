# Нотка 0.70 — исправления и GitHub-обновления

Комплект: APK 0.70, панель 0.61, редактор 0.83 «Обновления и стабильность». Ключ подписи тот же, что у APK 0.69. Старые опубликованные APK, ZIP и банки сохранены без изменения.

## Исправления

- Панель согласована с фактической версией APK и допускает встроенный редактор. Номера APK, панели, редактора и minApk задаются в release.json и синхронизируются перед сборкой. Диагностика сообщает правильную версию редактора.
- Совместимые редакторы остаются доступны, если каталог содержит пакет для будущего APK. Подпись и структура всего каталога по-прежнему проверяются; несовместимый пакет не запускается. Выбранная сервером совместимая latest сохраняется.
- Открытие библиотеки инструментов запускает получение подписанного каталога. Повторное открытие после неудачи позволяет повторить загрузку; при успехе лишний повторный запрос в той же сессии не выполняется. Уже загруженные звуки доступны без сети.
- Обычные внешние HTTPS-ссылки открываются отдельным Android-браузером. Внутренние ресурсы остаются локальными; file, javascript и intent URL не допускаются этим обработчиком.
- В Player включено DOM storage, которое требуется для сохранения настроек медиаэкспорта. Это не отменяет ограничения доступа WebView к сети и произвольным файлам.
- Локальный публикатор APK не заменяет существующий номер другими байтами. Режим проверки публикации теперь проверяет также размеры и SHA-256 всех перечисленных asset.

## Перенос обновлений

Каталоги, редакторы и звуки: `https://raw.githubusercontent.com/Vang1549/Notka/updates/dist`. APK: `https://github.com/Vang1549/Notka/releases/download/apk-<код>/Notka-<код>.apk`. Страница выпусков и ссылка на лицензии также ведут на GitHub.

Ветка main содержит разработку и подготовленный кандидат. Публикатор сначала размещает файлы GitHub Release, затем активирует ветку updates на тот же коммит. При сбое загрузки активный снимок не передвигается. Принудительное переписывание ветки не используется.

Старый Site не меняется. Существующий APK 0.69 сам не узнает новый адрес: для перехода один раз установить 0.70 вручную из Releases поверх 0.69. Для версии до 0.69 требуется согласованная ранее переустановка с предварительным экспортом треков из-за другого ключа подписи.

## Проверки

Полный прогон: **56 из 56 наборов прошли**. Проверены все 30 звуковых банков, 210 PCM-сэмплов и 30 MP3-предпрослушиваний.

Результаты полного прогона и SHA-256 конкретного кандидата фиксируются в [0.70.json](../release-reports/0.70.json) и [журнале](../release-reports/0.70-checks.log).

Проверка `test-release-panel.cjs` извлекает HTML-панель и метаданные встроенного редактора непосредственно из собранного APK, проверяет согласование версий, выбор редактора без сети и передачу правильного токена на запуск. Дополнительно проверяется смешанный каталог совместимых и будущих версий. Проверка звуков читает все 30 GeneralUser-банков по 7 сэмплов и декодирует 30 реальных MP3-примеров через FFmpeg.

NumPy 2.5.4, SciPy 1.18.1 и imageio-ffmpeg 0.8.1 устанавливаются в отдельную среду D:\Tools\Notka. Загрузки закреплены SHA-256; общие окружения не меняются. Воспроизводимая подготовка — `py -3.12 scripts/setup-sound-tests.py`.

Проверка моделей и готовых файлов не заменяет телефон. На физическом Android ещё не проверены реальный запуск WebView, переход в браузер, сохранение настроек, установка обновления, системные файловые диалоги и кодирование видео. Оригинальный авторский Floe-пакет отсутствует; только его отдельная проверка явно пропускается. Публичные данные и искусственный тестовый банк проверяются отдельно.
