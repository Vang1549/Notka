Музыкальный редактор для Android: дорожки и инструменты, piano roll, визуальный проигрыватель, сохранение проектов, экспорт музыки в аудио и видео.

Текущий комплект: **APK 0.69**, панель **0.60**, редактор **0.82 «Библиотека звуков»**. GitHub — основной репозиторий дальнейшей разработки. Здесь находятся актуальные исходники, подписанные пакеты, звуки, лицензии и инструкции сборки.

## Установка и обновление

Версия 0.69 подписана новым ключом. Перед переходом со старой Нотки экспортируйте нужные треки, удалите старую установку и установите `Notka-69.apk` из этого выпуска. Сохранённые старые пакеты редактора и инструментов проверяются по закреплённому прежнему открытому сертификату. Закрытый ключ хранится отдельно и в GitHub не публикуется.

Автоматические проверки сборки прошли; [отчёт](release-reports/0.69.json) и [журнал](release-reports/0.69-checks.log) включены в проект. На физическом телефоне эта сборка пока не проверялась.

Встроенный адрес проверки обновлений пока остаётся `https://notka-piano-updates.zentas.chatgpt.site`. Публикация исходников и выпуска на GitHub не меняет этот адрес и не публикует файлы на прежнем сайте. Новые банки и пакеты находятся здесь в `dist/`; перенос их автоматической раздачи требует отдельной настройки.

Android 5.0 и новее с актуальным для устройства WebView. Базовое пианино и Grand Piano встроены. Музыкальная шкатулка Music Box Suite Free импортируется пользователем из оригинального пакета Floe; сам пакет в репозитории не распространяется.

Минутное автосохранение, диагностика с экспортом JSON и оптимизация проигрывателя: [EDITOR-73.md](source/EDITOR-73.md). Диагностика включается на главном экране в настройках; показатели и журнал по умолчанию выключены.

## Структура

- `source/app/editor/` — исходные модули редактора; `source/app/index.html` генерируется сборкой.
- `source/app/launcher.html`, `source/app/media-export.js` — панель и медиаэкспорт.
- `source/native/`, `source/host.ops`, `source/updater_dex.py` — Android-службы и WebView-мост.
- `source/build.py` — сборка APK; `source/native-tools.json` закрепляет версии и SHA-256 инструментов.
- `source/test-*`, `source/native-tests/` — проверки поведения и форматов.
- `dist/bundles/`, `dist/editions/`, `dist/soundbank/`, `dist/channel.json` — подписанные обновления.
- `scripts/publish.py`, `publication.json` — публикация проверенных APK и архивов в Releases.

## Сборка

Нужны Python 3.10+, Java 21, Node.js и npm; Python-пакеты `cryptography` и `Pillow`.

```sh
cd source
npm ci
python -m pip install cryptography Pillow
# Владелец размещает исходный приватный signing.pem локально в source/.
python build.py
python verify.py
NOTKA_DIST=../dist node test-launcher.cjs
node test-grid-preview.cjs
```

Приватного ключа подписи здесь нет. `source/signing.der` — открытый сертификат для проверки выпусков. Для обновления существующих установок нужен исходный приватный ключ; он не должен попадать в Git, логи или архивы.

## Проверки

Из `source/`: `python -m pip install -r requirements-test.txt`, затем `npm test`. Команда запускает все автоматические наборы и явно показывает ошибки и пропуски. Подготовка сборки, зависимости и отдельная проверка оригинального Floe-пакета описаны в [TESTING.md](source/TESTING.md). Обновлять приложение на телефоне для изменений только в тестах не требуется.

## Выпуск обновлений

Новые пакеты редактора публикуются `source/bundle_channel.py` (APK 0.64+); старый формат сохраняет `source/editor_channel.py`, инструменты — `source/publish_instruments.py`. Уже выпущенные файлы редакторов и инструментов неизменяемы: новые изменения получают новый номер/идентификатор. Проверенные подписанные файлы из `dist` публикуются на основном сервере через Sites.

Для обычного нового APK сначала соберите и проверьте подпись, опубликуйте `dist/Notka-<код>.apk`, затем обновите подписанный `dist/channel.json`. Подготовленные выпуски помещаются в GitHub Releases: `apk-<код>/Notka-<код>.apk`.

Для крупных снимков GitHub файл `publication.json` описывает артефакты с фиксированными SHA-256. Workflow публикации запускается при изменении этого файла или вручную; он проверяет подписи каталогов и хеши, создаёт Releases и не заменяет уже опубликованный APK отличающимся файлом. Для следующих публикаций можно указать `path` к локальному файлу в репозитории вместо исходного `url`. Публикация CLI: `python scripts/publish.py` после входа `gh auth login`.

Подробности нового формата, ограничения распаковки и проверки: [EDITOR-72.md](source/EDITOR-72.md).
