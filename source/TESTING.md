# Проверки Нотки

На текущем Windows-ПК использовать из корня проекта `scripts/build-local.ps1`: команда собирает APK и выполняет выбранные проверки в подготовленной среде `D:\Tools\Notka`. Ключ берётся из `NOTKA_SIGNING_KEY` вне репозитория. `test-signing.py` и нативные проверки дополнительно проверяют новый ключ, закреплённый старый сертификат и отклонение подменённых данных. Подробности — в `../LOCAL-DEVELOPMENT.md`.

Из каталога `source/`:

```sh
python -m pip install -r requirements-test.txt
npm test
```

Запуск включает все `test-*.cjs`, все `test-*.py`, проверку подписи APK и каталогов, восстановление APK из дельты. `test-sound-host.cjs` — общий помощник, а не отдельный тест. Наборы Node запускаются в четырёх отдельных процессах; независимый Python-парсер MIDI/ZIP/WAV запускается после создавшего файлы теста экспорта. Ошибка или тайм-аут любого набора дают ненулевой код завершения. Пропуски отдельных проверок выводятся явно.

Нужны зависимости сборки из корневого README, `npm ci`, Java и подготовленные `.native-tools/`, `.native-build/`, текущий локальный APK. Перед проверками изменённого редактора выполнить `node build-editor.cjs`; запуск отклоняет устаревший `app/index.html`. Полная нативная сборка готовится через `python build.py`, но уже выпущенные файлы в `dist/` не заменяются. Тесты панели формируют подписанные сценарии с локальным `signing.pem`: исходный ключ остаётся только у владельца, в репозиторий его не добавлять. `npm test` ничего не публикует.

## Какие устаревшие проверки исправлены

- `test-editor6.cjs`: координаты относительно клавиатуры, заданный масштаб, управляемое время жестов, сохранение длины/громкости после удаления, текущий звуковой хвост, доступные названия клавиш. Перетаскивание, изменение длины, масштабирование двумя пальцами, отмена и индекс на 24 000 нот проверяются снова.
- `test-import.cjs`, `test-instrument-browser.cjs`, `test-personal48.cjs`, `test-source-links.cjs`: тестовый банк из `test-support/musicbox.cjs` содержит четыре искусственно созданных PCM-сэмпла. Он проверяет интерфейс, отмену/ошибки/подтверждение импорта, кэш, варианты удара, поиск, MIDI и работу с сохранениями без личных звуков. Grand Piano и старые публичные банки проверяются на их настоящих данных.
- `test-import-package.py`: структура нативного моста, шаблон и отсутствие личных звуков проверяются в текущем публичном APK из `dist/channel.json`, а не в старом APK 0.51.

## Оригинальный Floe и реальные устройства

Единственная необязательная проверка внутри `test-import-package.py` требует оригинального пакета автора. Искусственный банк её не заменяет. Для неё дополнительно нужен Python-пакет `soundfile`:

```sh
NOTKA_FLOE_PACKAGE=/absolute/path/musicbox.floe-pkg python test-import-package.py
```

Если переменная не задана, используется локальный `private-48/musicbox.floe-pkg`; отсутствие файла явно выводится как `SKIP` только для оригинального аудио. Явно заданный неверный путь считается ошибкой. Проверяются оригинальный SHA-256, ограничения архива, 31 стерео-FLAC, четыре варианта удара и PDF лицензии. Пакет и извлечённые звуки не сохраняются в репозитории.

Node-тесты используют модель DOM и аудиомоста. Они не подтверждают работу настоящего WebView, Android-установщика или реального аудиорендеринга. `test-web-audio.js` запускается вручную в браузерном предпросмотре, а установка, системный выбор файлов и звучание проверяются на телефоне отдельно.
