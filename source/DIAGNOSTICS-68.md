# Диагностика — APK 0.68 / панель 0.60

Сообщение пользователя: после записи сеанса в редакторе и проигрывателе экспорт из панели оставил пустой файл. На устройстве точную причину воспроизвести не удалось. В старом пути ACTION_CREATE_DOCUMENT создавал документ до получения результата; при ошибке последующей записи пустой документ оставался, проверки содержимого не было. Сводка панели и работа сборщика сами по себе не доказывают успешную запись внешнего файла.

На Android 10+ отчёт теперь пишется прямо в `Download/Notka` через MediaStore.Downloads. Запись имеет `IS_PENDING=1`, пока поток не закрыт и файл не прочитан обратно с побайтовым сравнением. Только затем запись публикуется. Текстовый файл `Notka-diagnostics-<дата-время>.txt` содержит полный JSON диагностики в UTF-8, удобный для вложения в чат. Содержание нот и звук не добавляются.

Android 5–9 сохраняет системный выбор папки. Режим `wt` имеет резервный `w` для несовместимых провайдеров. Пустая, обрезанная, изменённая запись, лишние байты, ошибки закрытия или публикации не считаются успехом; созданный документ удаляется по возможности. Исходный внутренний отчёт при любой ошибке экспорта остаётся. Запись/чтение внешнего документа выполняются в рабочем потоке с application context; размеры и путь сообщаются только после проверки. Отчёт, выбранный для экспорта, фиксируется до начала операции.

Чтение/запись внутренних AtomicFile синхронизированы в процессе панели: опрос статуса не конкурирует с завершением записи. Повторное нажатие во время экспорта не создаёт ещё один файл. После перезапуска процесса незавершённый статус разблокирует повторную попытку. Возвращение через native onResume, повторное открытие диагностики и visibilitychange обновляют состояние кнопки и результат. Для старого SAF callback устанавливается флаг экспорта до запуска рабочего потока.

Проверки: `python test-diagnostics-export.py` исполняет настоящий Java writer с моделями документных провайдеров, включая отказ `wt`, нулевую/частичную запись, битые/лишние байты, ошибки закрытия, публикации и очистки. `node test-diagnostics-panel.cjs` проверяет состояния панели, повторную попытку и отсутствие отчёта. Дополнительно стандартные нативные, APK-подпись и обновления панели. Физическое Android-устройство здесь недоступно: поведение MediaStore, системного файлового менеджера и прикрепления TXT в ChatGPT требует проверки на телефоне.
