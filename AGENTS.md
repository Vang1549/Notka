## Источник и публикация

Основной репозиторий: https://github.com/Vang1549/Notka, ветка `main`, аккаунт Vang1549. Локальный проект должен отслеживать эту ветку. Исходный Site и восстановленные локальные теги сохраняются как исторические источники; автоматически отправлять туда изменения не нужно.

Готовые APK и пакеты публикуются в GitHub Releases по `publication.json`. Существующий workflow выполняет проверку подписей и неизменяемости артефактов перед публикацией. Эта проверка уже существовала, не добавлять новые обязательные блокировки по полному набору тестов.

13 ноября 2026 владелец явно разрешил перенос обновлений на GitHub и публикацию новой версии. С APK 0.70 каталоги/редакторы/звуки загружаются из `https://raw.githubusercontent.com/Vang1549/Notka/updates/dist`, APK — из GitHub Releases. Публикатор передвигает ветку `updates` только после публикации всех файлов. `main` — разработка; `updates` — активированный снимок раздачи. Старый Site не изменять.

## Выпуски

Сохранять пакет `studio.notka.piano` и текущий сертификат `source/signing.der`. Для перехода на APK 0.69 владелец согласовал переустановку. Не публиковать приватный `signing.pem`, пользовательские треки и лицензируемые личные банки. `signing.der` открыт.

Выпущенные APK, ZIP редакторов и банки неизменяемы. Новое содержимое требует нового номера. APK размещать в `dist/Notka-<код>.apk`; сначала опубликовать и проверить файл, затем подписанный `dist/channel.json`. Для GitHub Releases использовать `scripts/publish.py` или существующий workflow. Развёртывание Sites выполнять только по отдельному указанию.

Перед APK: `python verify.py`, `python test-native.py`, `python test-background-service.py`, `python test-update-origin.py` из `source`. Перед панелью: `node test-launcher.cjs`, `node test-update.cjs`, `node test-catalog.cjs`. Для пакетов: `python test-bundles.py`, `node test-bundle-panel.cjs`, `node test-lazy-modules.cjs`. Подписи каталогов: `python scripts/publish.py --verify-only` из корня.

Доступен полный прогон `npm test` из `source/`; подготовка — в `source/TESTING.md`. Проверки выбирать по изменению. По решению пользователя не добавлять обязательную автоматическую блокировку публикации тестами. Существующие проверки поддерживать при изменении покрываемого ими поведения.

## Устройство

Исходники редактора — `source/app/editor/`, порядок в `modules.json`. `source/app/index.html` генерируется, править модули. Не возвращать большой HTML/base64 в Intent. Сохранять атомарную установку с проверкой подписи/хешей, сжатие и загрузку модулей из одной версии. Подробности: `source/EDITOR-72.md`.

Новые редакторы — `dist/bundles/`, исторические — `dist/editions/`, инструменты — `dist/soundbank/`. Совместимость старых редакторов сохранять. APK 0.63–0.64 имели фиксированные адреса GitHub: переход с них — одноразовая установка нового APK с обычного сервера поверх приложения, без удаления данных.

Минутное автосохранение, локальная диагностика и оптимизации проигрывателя: `source/EDITOR-73.md`. Диагностика по умолчанию выключена, содержимое нот и аудио в отчёт не включать.
